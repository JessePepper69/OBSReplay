# Documentation

Start with the document that matches your task.

| Task | Read |
| --- | --- |
| Understand what the app is for and the rules it keeps | [product.md](product.md) |
| Check if a feature is in scope, and its status | [scope.md](scope.md) |
| Change native code, the bridge, OBS control, settings or export | [architecture.md](architecture.md) |
| Change the interface, add a component or a theme | [design.md](design.md) |
| Run the checks, or see what has been tested | [validation.md](validation.md) |
| Plan a build that ships its own OBS | [research/standalone-obs.md](research/standalone-obs.md) |

## Conventions

- Each document describes the current state. Git history holds the past.
- The code is the source of truth. Fix the document when the two disagree.
- Identifiers appear in backticks, exactly as in the code. UI labels appear in **bold**.
- Paths are relative to the repository root unless a link says otherwise.
