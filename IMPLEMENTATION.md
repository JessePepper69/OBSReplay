# Module contract

Settings JSON keys: `obs_path`, `clips_dir`, `clip_seconds` (30..600), `capture` (`game`/`desktop`), `monitor_id`, `output_height` (0/720/1080/1440), `fps` (30/60/120/144), `encoder` (`auto`/`nvidia`/`amd`/`intel`/`cpu`), `codec` (`h264`/`hevc`/`av1`), `quality` (16/20/24), `mic_enabled`, `mic_device`, `desktop_device` (`default`/`off`/device ID), `noise` (`off`/`rnnoise`/`speex`), `separate_tracks`, `sort_by_app`, `save_sound`, `start_at_login`, `save_hotkey`, `show_hotkey`, `replay_enabled`.

`Controller::snapshot()` is a quick, mutex-protected JSON string. Keys: `settings`, `options`, `integration`, `obs_found`, `obs_running`, `connected`, `owned`, `replay_active`, `busy`, `operation`, `status`, `message`, `error`, `revision`, `clips`. Clips: `path`, `name`, `app`, `bytes`, `saved_at`.

Options keys: `monitors` (`id`, `label`, `width`, `height`), `audio_inputs`/`audio_outputs` (`id`, `label`), `encoders` (`id`, `label`, `codecs` array). Hardware probes run on worker, never snapshot/UI thread.

`dispatch(action,payload)` accepts an action into a bounded serialized native queue, or returns an error. Acceptance does not mean completion. The frontend observes `busy`, `message`, `error`, `revision` and actual state. Actions: `setup`, `apply` (payload is entire settings object), `start`, `stop`, `save`, `reconnect`, `reset`, `open_folder`, `open_obs`, `open_clip`/`reveal_clip` (payload `path`), `help` (payload `topic`), `refresh_options`. No arbitrary shell commands or URLs.

Main uses `saucer.exposed.snapshot()` and `dispatch(action,JSON.stringify(payload))`. `pick_folder(current)`/`pick_obs(current)` are native UI dialogs returning selected path or empty string. `quit()` exits controller while OBS stays active; `hide()` hides to tray. Main owns hotkey validation/registration on the UI thread and rejects conflicting settings submissions before queuing them. On failed apply, resynchronize bindings from persisted snapshot settings.

Setup returns resolved settings from Integration::prepare (e.g. actual encoder selection). It commits the dedicated profile, collection, shared WebSocket changes and resolved app settings in one rollback-capable transaction while OBS is closed. The controller updates its in-memory snapshot after that succeeds. Launch and buffer start are distinct operations. All platform code uses UTF-8 JSON and native wide paths. Dependencies are fetched at pinned versions; reference C# code and assets are not copied.

For configured sessions, Apply owns the restart: verify ownership and inactive stream/full-record outputs, preserve the current healthy buffer, stop replay, disconnect WebSocket, request a graceful close of the exact configured OBS process, run the configuration transaction, reopen and resume. Failed configuration attempts recover the prior capture. NVIDIA presets use OBS's CQVBR mode, resolution/FPS-scaled bitrate ceilings, P5, quarter-resolution multipass and adaptive quantization. A manifest marker enables the compression upgrade without requiring an unrelated setting change.

Clip editor (`src/editor.cpp`, `frontend/editor.*`): main exposes `open_editor(path)` for a confirmed recent clip; one editor window per clip (reopening focuses it). Each editor window has its own WebView2 view and media source restricted to that clip, and exposes `editor_state()` (clip, FFmpeg status/encoder, probe, waveform status, export job, saved quality), `editor_waveform()` (base64 peaks, 100/s), `media_url`, `start_export({segments:[[start,end]...], quality})`, `cancel_export`, `pick_ffmpeg`, `ffmpeg_help`, `reveal_output(reveal)` and `close_editor`. Edit decisions live in the page; native validates ordered, non-overlapping segments (max 100) against the probed duration. Analysis lists keyframes (packet scan), reads audio track names from stream metadata (`title`/`name`), copies every individual track to an audio stem (all tracks after the first when the first is a mix: OBS Mix, Desktop, Microphone), computes the waveform, then builds a 720p GOP-6 proxy (CUDA decode, `scale_cuda` and NVENC `p1`; CPU fallbacks), all in a per-editor `%TEMP%\OBSReplay-preview\<pid>-<id>-…` folder that is removed on close; folders from dead processes are swept at startup. `preview_urls()` serves those files through `ClipMedia::generated_url`. Range responses are capped at 4 MB windows, because WebView2 buffers a custom response stream completely before delivering it, which made each open-ended seek read the rest of the file. `save_pref(key, json)` validates and persists `quality`, `timecode`, `volume_master`, `track_volumes` (by track name), `scale` (applied as `ZoomFactor`; zoom control is disabled), `preview_cuts`. Analysis also lists every video packet (`framecrc`, well under a second) and records the clean cut points: closed-GOP keyframes whose decode index equals their frame number, plus the decode delay (B-frames). `editor_state().quality_plans` gives each level's video/audio bitrate, codec and height so the page can show the estimated size. Quality 10 (when the source is H.264/HEVC yuv420p with clean cut points and a matching encoder) is a smart cut: per kept section, frames before the first clean keyframe and after the last are re-encoded with the source codec (NVENC `-cq 18 -bf 0`, CUDA decode first, then CPU decode, then x264/x265) with `setts` giving them the source's decode delay, the middle is stream-copied with `-frames:v`, each part is written as MPEG-TS (in-band parameter sets), the parts are joined with an ffconcat list carrying exact frame durations, and audio is cut with `atrim` and re-encoded to AAC; the join must report exactly the kept frame count, otherwise the export falls back to a full re-encode. Quality 1–9 build one input per kept segment (`-ss/-t`; above 4 GPU or 16 CPU segments, one input with `trim`) and a `concat` filter for video plus every audio track, written to a filter file (`-/filter_complex`, or `-filter_complex_script` before FFmpeg 7), and encode at a share of the source video bitrate (HEVC `hvc1` with `hevc_nvenc` when the source is HEVC, otherwise H.264 NVENC with 1.35× the share, else x264), with CUDA decode and `scale_cuda` when available, AAC, and stream metadata copied so track names survive. The export writes `Edited Exports\… (edited).mp4.part` beside the source (or in the same folder when the source is already an export), then renames without overwriting, adds the file to clip history (`Controller::add_clip`) and reveals it in Explorer. FFmpeg children run hidden in a kill-on-close job; cancel or window close terminates them and deletes the partial file. Editor preferences (`ffmpeg_path`, `quality`) live in `editor.json` beside settings. `reconcile_clips` now removes only missing entries so concurrent additions survive.
